# TP-12 — Sign-in and offline (T04; PLAN §4, §10)

**What it proves** (Phase 4 §TP-12): with the Microsoft token expired and the iPad offline, all
editing works; sync shows "Sign-in needed" only when a sign-in is really needed; the silent
refresh succeeds once online. Manual, on an iPad with T04's build, against a server on
`AUTH_MODE=both` or `entra` with the "Field Survey" registration filled in (`docs/ops.md` §4.3).

What the Mac rig already proves (`rig.sh signin`, Simulator, fake registration): a token server
offers no Microsoft sign-in; a `both` server offers it while the token still syncs, and the sheet
opens and cancels; an `entra` server shows "Sign-in needed to sync" while an edit still queues and
syncs once the server takes the iPad again. It cannot sign anyone in to Microsoft or put an iPad
in airplane mode; that is this sheet.

## How the iPad behaves (for reading the results)

| Situation | What the iPad does | Status line |
|---|---|---|
| Access token has > 5 min left | sends it | `Synced …` |
| Access token expired or < 5 min left, online | refreshes silently with the refresh token (keychain), then sends | `Synced …` |
| Refresh cannot reach Microsoft (offline) | retries with the sync backoff | `Offline · n pending` |
| Microsoft refuses the refresh (expired, revoked, MFA or consent needed) | stops asking; every sync fails at once until someone signs in | `Sign-in needed to sync · n pending` |
| Server answers 401 to a token just obtained | same as refused (the server does not take this sign-in) | `Sign-in needed to sync` |
| Editing, any of the above | never waits for any of this | — |

The access token lives only in memory, so every cold launch starts with one refresh. Refresh
tokens for a public client last up to 90 days of inactivity (rolling; tenant policy can shorten
them); each refresh rotates it.

## Before you start

1. The server: `curl -s https://<server>/auth/config` shows `"mode": "both"` (or `entra`) and an
   `entra` block with the tenant and client id. Note the time.
2. The iPad has T04's dev build (or the TestFlight build made with it), is online, and is signed
   in with Microsoft (Sync → Install reads `Signed in with Microsoft (<email>)`).
3. A project with a level open, so there is something to edit.

## Checks

| # | Do | Expect | → saw |
|---|---|---|---|
| 1 | Sync → Sync now. | `Synced <time>`; nothing about sign-in. | |
| 2 | Airplane mode on. Close the app from the app switcher, open it again (the access token is gone from memory, so the first sync must refresh). Edit: a device status, a note, a photo, a new pin. | Every edit works at once. Status `Offline · n pending`, **not** "Sign-in needed". | |
| 3 | Still offline, wait past the access token's life (about 60–90 minutes; or leave it overnight). Edit again. | Edits still work; still `Offline`, not "Sign-in needed". | |
| 4 | Airplane mode off. Wait up to a minute or tap the status bar. | `Synced <time>`, pending back to 0, **no** Microsoft page shown (the silent refresh). The server has the edits under your name (Lists or another iPad). | |
| 5 | Revoke the sign-in: in the Entra admin centre → Users → you → **Revoke sessions** (or change your password). Wait a minute, cold-launch the app, edit something. | The edit works. Within a sync or two: `Sign-in needed to sync · 1 pending`; Sync shows "Sign-in needed to sync. Your Microsoft sign-in has run out or was refused…" and **Sign in with Microsoft**. | |
| 6 | Airplane mode on, tap **Sign in with Microsoft**. | Microsoft's page cannot load (or the sheet says offline); close it: nothing changes, edits stay pending. (Interactive sign-in is only useful online.) | |
| 7 | Airplane mode off, **Sign in with Microsoft**, sign in as yourself. | The sheet closes, "Signed in with Microsoft." The pending edit syncs; `Synced`, 0 pending. No merge question (you are already merged). | |
| 8 | Sync → Export local log → look for `auth_refreshed`, `auth_refresh_failed` (offline), `auth_refresh_refused` (after 5). | The lines match what you did. | |
